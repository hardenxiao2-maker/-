# B题乒乓球位置控制装置调试方法

## 1. 调试前检查

1. 确认 MSPM0G3507 主控、风机驱动电源和 ESP32 WiFi/蓝牙透传模块共地。
2. 确认 HC-SR04 接线：
   - Trig：PB12
   - Echo：PB13
   - VCC/GND 按模块要求连接
3. 确认风机 PWM 输出：
   - PA16：PWM 通道 1
   - PA17：PWM 通道 2
4. 确认按键为低电平按下：
   - PB25：目标距离减小
   - PA29：目标距离增加
   - PB26：启动/待机切换
5. 确认无线模块 UART2 接线：
   - PB15 / UART2_TX -> 模块 RXD
   - PA22 / UART2_RX <- 模块 TXD
   - 波特率：115200

## 2. 主程序调参入口

常用调试参数集中在 `empty.c` 顶部：

```c
static const HoverDebugConfig_t HOVER_TUNE = { ... };
static const HoverDistanceCalPoint_t HOVER_DISTANCE_CAL[] = { ... };
```

调试时优先只改这两块，改完重新编译并下载。

## 3. 超声波距离校准

校准表格式为：

```c
{超声波测得值, 真实距离}
```

例如真实球心距离为 20cm 时 OLED 显示 18.7cm，真实 25cm 时 OLED 显示 23.9cm，则填写：

```c
{18.7f, 20.0f},
{23.9f, 25.0f},
```

推荐标定点：

```text
20cm, 25cm, 30cm, 35cm, 40cm, 45cm, 50cm, 55cm, 60cm, 65cm, 70cm
```

注意：
1. 表左侧“测得值”必须从小到大排列。
2. 每个点建议重复读 5 次，取平均值再填入表格。
3. 程序会在相邻标定点之间做线性插值，不需要每 1cm 都标定。
4. 如果表格顺序填错，程序会自动禁用校准，直接使用原始测距值。

## 4. 静态测距调试

1. 先不启动风机，保持系统处于 `STANDBY`。
2. 将球放在已知真实距离位置，观察 OLED 的 `Actual`。
3. 若误差稳定但有偏差，修改 `HOVER_DISTANCE_CAL`。
4. 若数值跳动明显，优先检查：
   - 球是否正对超声波传感器
   - 导槽内是否有强反射边缘
   - Echo 引脚是否接触不良
   - `filter_alpha` 是否过大

`filter_alpha` 建议：

```text
0.20 ~ 0.30：显示更稳，响应稍慢
0.35：当前推荐值
0.45 ~ 0.60：响应更快，但更容易抖动
```

## 5. 基础风量 base_pwm 调试

先把 PID 调弱，主要寻找能托起球的基础风量：

```c
.kp = 0.0f,
.ki = 0.0f,
.kd = 0.0f,
```

然后逐步调整：

```c
.base_pwm = 350.0f,
```

判断标准：
1. 球完全不动：增大 `base_pwm`。
2. 球一启动就冲上去：减小 `base_pwm`。
3. 球能接近目标区间但还会缓慢滑动：基础风量基本合适，可以开始调 PID。

## 6. PID 调参顺序

建议按下面顺序调：

1. 只调 `kp`
   - 从小到大增加。
   - 目标是小球能明显向目标距离回正。
   - 如果开始持续上下振荡，说明 `kp` 偏大。
2. 加入 `kd`
   - `kd` 用来抑制冲过目标点。
   - 若小球冲过目标后往返摆动，适当增加 `kd`。
   - 若风机声音高频抖动、PWM 变化尖锐，说明 `kd` 偏大或测距噪声过大。
3. 最后加入 `ki`
   - `ki` 用来消除长期偏差。
   - 若小球总是稳定在目标点上方或下方几厘米，可少量增加 `ki`。
   - 若小球慢慢越吹越偏，最后冲出，说明 `ki` 或 `integral_max` 偏大。

## 7. 功能4无线通信调试

当前功能4采用手机 App 连接 ESP32 WiFi/蓝牙二合一透传模块，单片机通过 UART2 与模块通信：

```text
App -> WiFi -> ESP32 透传模块 -> UART2_RX(PA22) -> MSPM0G3507
MSPM0G3507 -> UART2_TX(PB15) -> ESP32 透传模块 -> WiFi -> App
```

通信协议：

```text
遥测上传：T,ms,active,target_cm,current_cm,pwm
控制命令：RUN / STOP / UP / DOWN / SET 50 / GET
```

已完成的实测检查：
1. App 可接收 `T,...` 遥测数据，说明上行链路正常。
2. App 点击启动/停止后，单片机可切换 `ACTIVE/STANDBY`，说明下行链路正常。
3. 实体按键切换状态后，App 界面能同步显示状态变化。
4. App 的 `UP`、`DOWN`、`SET` 命令可改变 OLED 显示的目标距离。

## 8. UART2 接收丢字节问题与修复

调试过程中曾出现“App 日志显示 `TX RUN`，但单片机不切换状态”的问题。通过 OLED 显示 UART2 原始接收字节、再进行 TX/RX 自环回测试，发现单片机主循环轮询接收时只能读到末尾换行符，前面的 `RUN`、`STOP` 等字符丢失。

根因是主循环中存在 OLED 刷屏和超声波测距等耗时任务。115200bps 下串口数据到达很快，而 UART 硬件 FIFO 容量有限；当 CPU 正在执行耗时任务时，FIFO 发生溢出，导致前面的字符丢失。

最终修复方案：

```text
UART2 RX 中断 -> 128 字节软件环形缓冲区 -> 主循环解析完整命令
```

修复后，串口接收不再依赖主循环及时轮询，即使 OLED 刷屏或测距任务耗时较长，也不会漏掉 App 下发的控制命令。

## 9. 常见问题定位

### OLED 一直显示 Actual: Error

检查 HC-SR04 是否接反，PB12/PB13 是否连接正确，Echo 是否存在电平兼容问题。

### 按键没有反应

程序按低电平作为按下判断。确认按键按下时对应引脚会被拉到 GND。

### App 能接收数据但控制无效

1. 检查 App 日志是否出现 `TX RUN` 或 `TX STOP`。
2. 检查模块 `TXD` 是否接到 MSPM0 `PA22/UART2_RX`。
3. 检查 UART2 是否为 115200bps。
4. 确认当前固件已使用 UART2 中断 + 环形缓冲接收，不再使用主循环直接读取 UART FIFO。

### 球容易飞出

优先降低：

```c
.base_pwm
.pwm_max
.kp
.ki
.integral_max
```

### 球响应太慢

优先提高：

```c
.base_pwm
.kp
.filter_alpha
```

但每次只改一个参数，避免判断不出原因。
